## Key rulings made on the owner's behalf (M4a + M4b) — full reasoning in the PRs

1. **Token handling (security-critical, M4b final review):** the sandbox clone is
   CREDENTIAL-FREE (git env-based `http.extraHeader`, token via per-run Secret
   env; never in URL/argv/`.git/config` — the workspace is agent-readable). The
   Gitea token is the platform ADMIN token for v0 (owner-approved builder-check
   exception to "read-only sandbox credentials"; per-project read-only tokens are
   the M4c/M5 line).
2. **Vault-only worker path:** the worker resolves the Gitea token from OpenBao
   BEFORE the first host git call; the m4b acceptance runs WITHOUT
   `AGENT_RUNTIME_GIT_TOKEN` on purpose.
3. **done_when/paths_allow are validated by code, never an LLM**; unparseable
   done_when → FAIL (`unparseable_done_when`); empty allow-list denies everything;
   per-section diff path attribution (rename/copy guard both sides);
   `DiffUnparseable` on non-empty unparseable diffs → vertex FAIL.
4. **Sandbox pod**: derived git-enabled image (`SANDBOX_IMAGE` = `opencode-git:<tag>`)
   — the official image has NO git and the diff endpoint requires it; PVC mounted
   into BOTH containers; **no `OPENCODE_DB`** (breaks harness snapshots); full
   clone (not shallow); `--print-logs` on serve.
5. **Evidence is host-side** (the adapter's SSE pump writes session_log.ndjson +
   manifest.json into `evidence_root`); no pod-unload channel exists.
6. **Heartbeat-409 or transport error → ABANDON** the vertex (control plane
   requeues via lease expiry); never complete/fail a lost lease.
7. **v0 = ONE worker per run** — the age-based orphan sweep is unsafe with
   concurrent workers (documented in settings + STATE.md).
8. **Executor model on the stand: `litellm/qwen3`** — qwen2.5-coder:7b
   (`qwen-coder`) returns tool-calls as assistant TEXT and cannot drive the
   harness; the flows' preflights assert the `tool_calls` property so a wrong
   model fails in ~40 s.
9. **LiteLLM endpoint must include `/v1`** (opencode openai-compatible provider
   appends its own paths to baseURL).

## Operational lessons for a NEW workstation (Windows)

- **The live stand does NOT transfer.** k3d cluster `swarm-lab`, OpenBao keys
  (`infra/.vault-root-token`, `infra/.vault-unseal-keys.json` — both gitignored,
  machine-local), colima VM — all were local to the macOS laptop. On the new
  machine: run `uv run org-bootstrap apply` from scratch (m2d_flow is the E2E
  bootstrap check); it auto-init/unseals OpenBao and writes NEW local keys.
- **OpenBao seals on host restarts** — flows reading secrets must unseal first
  (keys in `infra/.vault-unseal-keys.json`, `bao operator unseal <key0>`; the
  m4b/m4a flows' preflight pattern in m4b_flow.sh shows the guard).
- **k3d publishes only individually mapped NodePorts**; the sandbox NodePort
  range 30100–30110 is added by `section_agents` via
  `k3d cluster edit --port-add` (idempotent guard) — no cluster recreation.
- **macOS-specific residue:** the colima host IP (192.168.5.2) appears in a few
  places (LiteLLM hostAliases for the DOCKER executor path — resolved dynamically
  in `section_litellm`; one hardcoded `192.168.5.2` remains in the m4b netpol
  probe as the "host NodePort" denial target). On Windows/Docker Desktop
  `host.docker.internal` works natively; expect to adjust the host-IP literal
  and possibly `infra/k3d/config.yaml` port mappings.
- **The acceptance flows are bash** (`infra/tests/*.sh`, `bootstrap.sh`) — on
  Windows use WSL2 (or Git Bash) with docker+k3d available inside it.
- **Provider access:** this session's subagent work ran on `openrouter`
  models (the `opencode-go` provider models hit "Go usage limit" mid-session —
  do not rely on them). Local LLM: Ollama with `qwen3` (and
  qwen2.5-coder:7b present but unusable by the harness, see ruling 8).
- **Transient LiteLLM pod recreation** (probable memory-pressure eviction during
  LLM load) can flake preflight checks — just rerun the flow.
