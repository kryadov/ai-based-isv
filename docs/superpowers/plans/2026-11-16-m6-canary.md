# M6 Canary Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner pre-authorized inline execution). Steps use checkbox (`- [ ]`) syntax.

**Goal:** a merged change to `isv-product` reaches `prod` as an Argo Rollouts canary. Prometheus analysis against the stable version and a post-rollout window decide the outcome: a success marker, or an automatic rollback with a postmortem.

**Architecture:** the worker's deployer builds the image on the shared moby store, overrides the image on the Argo CD Application and watches the Rollout to a verdict. The AnalysisTemplates query kube-prometheus-stack. k6 generates the traffic. Agents get read-only deploy and observability MCP tools.

**Tech Stack:** FastAPI + prometheus-client, Argo Rollouts (Helm), Argo CD (kustomize), k6, Python 3.12, httpx, pytest, bash/toolbox.

**Spec:** `docs/superpowers/specs/2026-11-16-m6-canary-design.md`

## Global Constraints

- Prod namespace `prod`; Argo CD AppProject `swarm-lab`; Prometheus at `http://kube-prometheus-stack-prometheus.platform:9090`.
- Canary steps: `setWeight 20` → pause 60s → `setWeight 50` → pause 60s → `setWeight 100` → analysis `post-rollout`. Background analysis `canary-vs-stable` while the canary runs. 4 replicas.
- Thresholds:
  - canary 5xx ratio ≤ max(stable × 2, 0.05);
  - canary p95 ≤ max(stable × 1.5, 0.3 s);
  - post-rollout: the same bounds against the baseline the deployer passes;
  - interval 30s, count 4, failureLimit 1.
- Image naming: `isv-product:<sha7>`, `imagePullPolicy: IfNotPresent`.
- Fault env: `FAULT_ERROR_RATE` (0..1) and `FAULT_LATENCY_MS`; defaults 0.
- `deploy/**` joins the global `PROTECTED_GLOBS`.
- A rollback is terminal for the vertex: `POST /vertices/{id}/fail` with `{"terminal": true}` sets status `failed`. A HITL reject uses the same flag.
- The argo-rollouts chart is pinned to a release at least two weeks old. No `git add -A`. English in code and docs, `*.ru.md` mirrors.
- LLM: z.ai only until its limit.

## Review Focus

1. **Prometheus has no samples yet** (fresh service, empty vectors). The analysis must use the absolute floors, not fail or pass vacuously on NaN. Pinned in Task 2: the PromQL uses `or vector(0)` and a test asserts it.
2. **The deployer watch times out while the Rollout is still progressing.** The verdict must be `timeout`, with the Rollout left as is and no false success. Pinned in Task 6.
3. **A second deploy of the same sha** (image already present). It must be idempotent: a rebuild is a no-op and the Application is already on the target. The verdict is `succeeded` without a new rollout. Pinned in Task 6.
4. **An agent PR touching `deploy/rollout.yaml`.** It must be blocked as a protected path. Pinned in Task 4.
5. **A terminal fail called by a non-leasing agent.** It must return 409, like the requeue. Pinned in Task 4.

### Task 6: Deployer

**Files:** Create `packages/agent_runtime/src/agent_runtime/deployer.py`. Test: `packages/agent_runtime/tests/test_deployer.py`.

**Interfaces:**
- `DeployVerdict(status: Literal["succeeded","rolled_back","timeout","rejected"], image: str, revision: str, analysis: list[dict[str, Any]], baseline: Slo, started: str, finished: str, postmortem: str | None)`.
- `class KubePort(Protocol)` with:
  - `app_image() -> str | None`;
  - `set_app_image(image, *, args: dict[str, str], fault_env: dict[str, str]) -> None`;
  - `rollout() -> dict` (the Rollout JSON);
  - `analysis_runs() -> list[dict]`;
  - `has_stable() -> bool`;
  - `build(sha: str, repo_dir: Path) -> str` (the image).
- `async def deploy(sha, repo_dir, *, kube: KubePort, slo: Callable[[], Awaitable[Slo]], hitl: HITLPort, deploy_paths_changed: bool, fault: dict[str,str] | None = None, timeout_s: float = 900, poll_s: float = 10, sleep=asyncio.sleep, now=...) -> DeployVerdict`.
- `def write_postmortem(verdict: DeployVerdict) -> str` (markdown).
- The real `KubectlPort` uses kubectl JSON. CLI: `python -m agent_runtime.deployer --sha --repo-dir [--fault k=v]`.

Steps:

- [ ] Tests with a FakeKube scripting rollout phases:
  - `test_success_marks_succeeded`: phases Progressing → Healthy, image matches → `succeeded`, analysis copied;
  - `test_degraded_rolls_back_with_postmortem`: phase Degraded with `status.abort=true`, failed AnalysisRun → `rolled_back`, and the postmortem mentions the failed metric and threshold;
  - `test_timeout_leaves_rollout`: always Progressing → `timeout`, no further set_app_image calls;
  - `test_first_rollout_requires_hitl`: `has_stable False` → HITL created with kind `deploy`; rejected → `rejected` and no `set_app_image`;
  - `test_deploy_paths_changed_requires_hitl`;
  - `test_same_image_is_noop_success`: `app_image == target` and phase Healthy → `succeeded` without `set_app_image`;
  - `test_fault_env_passed_through`;
  - `test_baseline_args_passed` (`baseline-error`, `baseline-p95` strings).
- [ ] FAIL → implement → PASS.
- [ ] Implement `KubectlPort`:
  - patch the Argo CD Application (`kubectl -n platform patch application isv-product-prod --type merge`) with `spec.source.kustomize.images` and `spec.source.kustomize.patches` for env and analysis args;
  - build with `docker build -t isv-product:<sha7>`, plus `k3d image import` when `SWARM_CLUSTER=k3d`.
