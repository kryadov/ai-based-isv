# M2a: Vault + Postgres(pgvector) + Gitea на k3d — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, выбор владельца — «оптимально по токенам, качество важнее») для реализации плана задача-за-задачей. Шаги с чекбоксами (`- [ ]`).

**Goal:** L0-ядро на ноутбуке: k3d-кластер + Vault + Postgres(pgvector) + Gitea (с act_runner и OCI-registry); приёмка — работающий PR-flow с branch protection, проверяемый скриптом.

**Architecture:** всё декларативно в `infra/`: конфиг k3d, helm-values, K8s-манифесты; `infra/bootstrap.sh` — идемпотентный оркестратор (helm upgrade --install + kubectl apply + wait); env-манифест `infra/env.yaml` — артефакт VET (endpoint'ы, версии). Манифесты идентичны для будущего k8s (спека §3).

**Tech Stack:** k3d, helm v4 (charts: gitea, hashicorp vault, cloudnative-pg), CNPG operator + image `pgvector/pgvector:pg17`, act_runner (dind sidecar), bash + curl для acceptance.

**Spec:** `docs/superpowers/specs/2026-11-07-swarm-dev-platform-design.md` (§3, §6 таблица L0, §6.1, §10 M2a; решение владельца: всё на ноутбуке, k3d)

## Global Constraints

- Namespace'ы: `platform` (gitea, vault, postgres, runner). Не использовать `default`.
- NodePort'ы наружу: Gitea HTTP `30080`, Gitea SSH `30022` (k3d port-mappings).
- Все версии чартов/образов пинятся в `infra/env.yaml`; `latest` запрещён.
- Секреты администратора Gitea хранятся в Vault (`secret/gitea/admin`), в git не попадают; `infra/.bootstrap-admin-token` и `infra/env.yaml.local` — в `.gitignore`.
- Идемпотентность: повторный `infra/bootstrap.sh` не ломает работающий стенд (helm upgrade --install, kubectl apply, wait).
- Приёмка M2a (критерий из спеки §10): PR-flow целевого репо с branch protection работает — `infra/tests/m2a_pr_flow.sh` зелёный.
- Каждый инкремент поставляет md-доки (требование владельца): INSTALL.md обновляется в Task 1 и финализируется в Task 8.

## Review Focus

1. Повторный `infra/bootstrap.sh` на живом стенде не должен пересоздавать PVC/данные Gitea (идемпотентность) — проверяется повторным прогоном в Task 7.
2. `--locked`-манифесты не зависят от порядка поднятия: bootstrap должен ждать readiness (helm wait / kubectl wait), а не спать.
3. Токен администратора Gitea не должен появиться в git (grep по истории/working tree в Task 8).
4. `m2a_pr_flow.sh` должен падать (не молча проходить), если Gitea API недоступен — set -euo pipefail + явные curl-проверки кодов ответа.
5. На arm64: все образы multi-arch (gitea, vault, pgvector/pgvector, act_runner) — иначе pod CrashLoop на ноутбуке; проверка в Task 6 по статусу подов.
