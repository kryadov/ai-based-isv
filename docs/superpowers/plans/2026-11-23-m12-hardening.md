# M12 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** close the stand's LAN exposure, split the service token per identity, add task retry, graceful worker shutdown, panel e2e in CI, and drop secrets from command lines.

**Architecture:** static bearer middleware on task-source MCP (like agent_api M11); agent_api matches the bearer against `name:sha256` pairs and scopes HITL decisions to `operator`; retry = a new vertex-less pending run that the existing dispatcher plans; shutdown = a lease release endpoint + SIGTERM handling.

**Tech Stack:** Python 3.12, FastAPI, FastMCP 4.1.8 (Starlette), httpx, pytest, bash, PowerShell 5.1, GitHub Actions, Playwright 1.49.

**Spec:** `docs/superpowers/specs/2026-11-23-m12-hardening-design.md`

## Global Constraints

- `mypy --strict`, ruff check+format, pytest green; TDD for every code change.
- Tokens never on argv, never logged; compare with `hmac.compare_digest`.
- English in code/docs; `.ru.md` mirrors updated for TODO/STATE-facing docs.
- Back-compat: an unset token env keeps today's open behaviour (host-run flows).

## Review Focus

- A request with `Authorization: Bearer ` (empty) or a wrong scheme must be 401, never treated as "no token configured".
- Retry label on an issue whose newest run is still `pending` must not create a second concurrent run.
- Release by a worker that no longer holds the lease must be a 409 and must not touch `attempts`.
- `attempts` must never go negative on release.
- SIGTERM arriving while no vertex is held must exit the loop promptly without API calls.
